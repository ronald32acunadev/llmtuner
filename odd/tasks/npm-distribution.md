# Feature: npm distribution

Locator: `odd/tasks/npm-distribution.md` · Engram topic: `odd/npm-distribution/tasks`

## Objective

`npm install -g llm-tuner` gives the user the `llm-tuner` CLI and the `llm-tuner-desktop` app, and a push to the `release` branch publishes a new version.

## Problem and why

The project is only usable from a clone. The owner considers it stable and wants it installable like any npm CLI, with the desktop app included.

## Scope

In: package manifest, launcher as an installed command, removal of the user-facing web mode, CI and release workflows, documentation.

Out: update notice, npm trusted publishing, CI on Windows and macOS. Creating the npm account, the token, the GitHub environment and the `release` branch, and publishing, are the owner's actions.

## Constraints

- Node >= 22, ESM, no build step, no new dependencies.
- `src/web/` is not modified.
- User-facing strings go through `src/i18n` in `en` and `es`.
- Code under `src/`, `electron/` and `test/` is requested from `pumbastudio` first (`AGENTS.md`).
- The Linux desktop entry and icon work from commit `bfc0295` is kept.

## Acceptance criteria

- `npm pack` ships `src/`, `electron/`, both READMEs and `LICENSE`, and nothing from `test/`, `docs/`, `odd/` or the agent folders.
- Both commands start with a shebang and are declared in `bin`.
- A desktop runtime that cannot start gives one localized message and exit code 1, with no stack trace.
- The CLI help has no `--web` option and the CLI does not import the web server.
- `npm test` passes.

## Checks

- Per task: the focused test file, then `npm test`.
- T-4: YAML parse and read-back; GitHub validates the workflows on the first pull request and the first release.
- T-6: install from the tarball into a temporary prefix.

## Decisions taken during execution

- Based on `bfc0295` instead of `origin/main`: the owner's desktop icon commit and `5229f09` are not on `main`. The pull request to `main` will carry those two commits.
- `build.linux.desktopName` (added in `bfc0295`) goes away with the `build` block: it is an `electron-builder` option. The runtime desktop entry in `electron/launch.js` and `app.setDesktopName` in `electron/main.js` stay.
- `electron/launch.js` is edited in place instead of rewritten, to keep `ensureLinuxDesktopEntry`.
- The launcher test sets `XDG_DATA_HOME` to a temporary directory so it never writes a desktop entry into the real home.
