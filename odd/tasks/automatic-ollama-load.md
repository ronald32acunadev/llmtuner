### Proposed design

**Shared flow.** Keep configuration deterministic and interface-independent. Compare the requested server environment with the effective configuration of the local Ollama service, including running-process state where needed to distinguish configured values from active values. Reuse unchanged settings without restarting. When settings differ, apply them with a backup, obtain the required OS authorization, restart only as needed, wait for readiness, and then load the model. A failed restart or an authorization cancellation must prevent loading and must not be reported as success.

**Desktop.** The Electron/server adapter supplies native authorization for the Linux systemd service through the installed OS authorization facility. The renderer cannot supply privileged command strings, executable paths or destination paths. No polkit agent or a cancelled dialog produces a localized actionable failure, not a success or an attempt to bypass consent.

**Console.** The interactive CLI supplies terminal-based administrator authorization. Pause the animation while the terminal owns the prompt; never read, store or log the password in JavaScript. Resume the same load after successful authorization. Proposed safe assumption: a noninteractive or JSON invocation must never wait for a password; it can continue with already available authorization, otherwise it fails clearly without claiming the model loaded.

**Privilege boundary.** Authorize only a fixed built-in operation for the local Ollama systemd environment. Validate candidate values before elevation and keep command structure and destinations fixed. Do not execute caller-writable scripts or elevate arbitrary returned `pendingCommands`. Back up any existing engine configuration before replacing it. Reject unsupported or remote service targets rather than treating local privileges as permission to control them.

**Scope.** The new privilege flow targets the existing Linux systemd path that failed here. Preserve existing Windows/macOS behavior and the no-systemd fallback; do not claim those paths have the new administrator UX. Do not change estimator math, profile rules, model selection, dependencies or unrelated installers. Missing native authorization facilities remain an explicit limitation.

**Why this route.** Keep the existing Ollama service so other clients retain the same endpoint and configuration. A permanent private server would avoid changing that service, but introduces another lifecycle and endpoint; it is not the selected design.

**Verification.** Use isolated configuration and fake executables, never the real service, for deterministic RED/GREEN tests. Cover unchanged settings, changed settings, backup preservation, denied/cancelled authorization, command failure, readiness failure, desktop completion status, interactive CLI behavior and noninteractive/JSON behavior. Pin the existing dry-run and unrelated load behavior. Run focused tests, the complete suite and an independent security/environment verifier. Real CUDA loading remains a separate explicitly authorized runtime check.

#### T2 — Reconcile the local service safely (S1-S2)

Files: create `src/core/engines/ollama-service.js` and `test/ollama-service.test.js`; modify `src/core/engines/ollama.js`, `test/engines.test.js`, and the Ollama section of `docs/PROYECTO.md`.

Interfaces:
- `validateServiceEnv(env)` returns a normalized object containing only `OLLAMA_FLASH_ATTENTION`, `OLLAMA_KV_CACHE_TYPE`, `OLLAMA_NUM_PARALLEL`, and the optional GPU-order pair. Reject unknown keys, invalid enum/integer values, duplicates in GPU order, control characters, and shell metacharacters before any operation.
- `reconcileOllamaService(apiUrl, env, { authorize })` returns `{ changed, restarted, backups }`. Accept only the local default Ollama endpoint for this system-service operation. Unknown running state must not count as a match. `authorize({ operation: 'ollama-service-env', env })` is a trusted callback supplied outside the core, never a renderer-provided command.
- A fixed built-in privileged operation compares live environment, writes only the fixed Ollama drop-in when needed, preserves a `*.bak-llm-tuner-*` backup, reloads systemd when configuration changes, and restarts only when live settings differ. It accepts validated values, not scripts, executable paths or destinations. Refuse symlinked/untrusted destinations and concurrent replacement conflicts. Do not copy a user-writable temporary script/config as root.
- `ollama.apply(ctx, model, candidate, { authorize, ...existingOptions })` calls reconciliation only for the Linux systemd path after dry-run/confirmation. Existing non-systemd/platform behavior remains intact. Check command results and poll API readiness with a bounded deadline before returning success; failed or cancelled setup throws a localized `TunerError` and does not load.

Web completion is successful only for an actually successful load, not for pending commands.
