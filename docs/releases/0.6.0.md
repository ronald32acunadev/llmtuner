# LLM Tuner 0.6.0

Release candidate. Publication is a separate step tracked in [the release story](../userstories/release-0-6-0/README.md).

## Highlights

- **Conversation in the CLI**: new `/chat` command with a guided loop, plus `--prompt` for one scripted message. It works on the local or the selected remote computer.
- **Confirmation before applying**: Desktop and the remote CLI show the proposed changes and wait for your answer. An unanswered confirmation is declined after two minutes, or when the connection drops. `--yes` still skips it in the CLI.
- **Dry run everywhere**: `--dry-run` now works against a remote computer, and Desktop has a **Dry run** option. It can still unload models and run real measurements.
- **Candidate count in Desktop**: choose how many configurations to measure.
- **First-model download in Desktop**: download a named model when the local list is empty. Remote callers and remote targets are refused.
- **Saved presets panel in Desktop**: list and filter all presets from the sidebar.
- **Share this computer from Desktop**: start the shared server from Settings, with the same host, port and token rules as `/serve`.
- **Guided saved computers in the CLI**: add, test, select and remove them from Settings.

## Behavior Changes

- Node.js 24 is now the minimum version, and CI tests and publishes on it.
- `--candidates` and the API's `candidates` field now refuse anything but a positive whole number. Previously invalid CLI values silently became 3, and the API coerced numeric strings.
- Saving a server in Desktop no longer selects it. Choose it from the list. Removing one now asks for confirmation.
- `/serve` keeps the saved configuration unchanged if the server cannot start, and saves the port actually bound.
- A remote CLI load now shows pending commands and load errors instead of failing with a generic message.
- `/mcp` asks for the server name before the agents, and reports existing configuration against that name.
- In Desktop, **Start sharing** with the suggested IP listens only on that address. Enter `0.0.0.0` to listen on all interfaces. `/serve` still defaults to `0.0.0.0`.

## Fixes

- A remote that drops during a proxied load no longer crashes the local server.
- Values from a remote computer are escaped before reaching the Desktop page.

## Compatibility

- **Node.js 24 or later is now required**, up from 22. Update Node before upgrading. Dependencies are unchanged.

## Not Proven

- Confirmation, first-model download and shared hosting have automated and browser evidence, but were not run end to end in a real Electron window.
- No real GPU benchmark, model download or remote host was exercised for this release.
- Native review was declined for these changes.

## Known Issues

- `--candidates=abc`, written with `=`, is ignored: the CLI parser only supports `--candidates abc`.
- The CLI's loaded message prints a literal `{ctx}`.
